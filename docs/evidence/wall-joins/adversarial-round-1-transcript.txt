//! Union of simple polygons by boundary classification.
//!
//! # Why a union at all
//!
//! BEHAVIOR-SPEC R3.2.1 defines a wall cluster's occupied region as the UNION
//! of each wall's butt-capped rectangle and each join's patch, and R5.1.1
//! defines the rooms of a level as the bounded components of the complement of
//! that region. Both the drawing and the floor area therefore depend on one
//! operation: unioning overlapping rectangles into a single boundary.
//!
//! # How it works
//!
//! Every input ring is oriented counter-clockwise, so each directed edge
//! carries its polygon's interior on its LEFT. Edges are split at every mutual
//! intersection, after which an edge fragment is either wholly inside another
//! polygon, wholly outside every other polygon, or exactly coincident with a
//! fragment of another polygon. Each case has one rule:
//!
//! - A fragment with a REVERSED twin has union interior on both sides — the
//!   two polygons meet back to back — so it is not on the union boundary.
//! - A fragment strictly inside another polygon is not on the union boundary.
//! - Anything else is on the boundary; same-direction duplicates keep one copy.
//!
//! The surviving directed edges are then traced into rings by always taking
//! the first outgoing edge encountered when sweeping CLOCKWISE from the edge
//! we arrived on. That is the `next` rule of a doubly connected edge list for
//! a face lying to the left of its boundary, and it splits a vertex where two
//! components touch at a single point into two simple rings rather than one
//! figure-eight — which is what R5.1.2 requires of pinch points.

use crate::arrangement::classify_point;
use crate::arrangement::{cut_params, lerp, ring_contains_ring, Containment, VertexKey, WELD_MM};
use crate::polygon::{canonical_ring, compare_polygons, signed_double_area, Polygon, Winding};
use domowik_format::Point;

/// The union of `rings`, as canonical polygons with holes.
///
/// Each input is treated as a simple closed ring; winding is normalized, so
/// callers need not supply a particular direction. Rings that enclose no area
/// contribute nothing: a degenerate join patch (R3.2.3) is a closed segment
/// through the join node and is always covered by the cross-section it came
/// from, so dropping it changes neither the region nor its boundary.
///
/// Output is deterministic: components are sorted by the R3.2.4 canonical
/// ordering, so the same document always renders the same sequence.
pub fn union(rings: &[Vec<Point>]) -> Vec<Polygon> {
    let inputs: Vec<Vec<Point>> = rings
        .iter()
        .filter_map(|r| canonical_ring(r, Winding::CounterClockwise))
        .collect();
    if inputs.is_empty() {
        return Vec::new();
    }

    let fragments = split_all(&inputs);
    let kept = classify_fragments(&inputs, &fragments);
    let rings = trace_rings(&kept);
    assemble(rings)
}

/// A directed edge fragment and the index of the polygon it came from.
struct Fragment {
    owner: usize,
    from: Point,
    to: Point,
}

/// Splits every ring edge at every intersection with every other ring's edges.
///
/// Edges of the SAME ring are not cut against each other: inputs are simple
/// rings, so their own edges meet only at shared endpoints, and passing them
/// through the collinear-overlap test would cut every edge at its own
/// neighbours for nothing.
fn split_all(inputs: &[Vec<Point>]) -> Vec<Fragment> {
    let edges_of: Vec<Vec<(Point, Point)>> = inputs
        .iter()
        .map(|ring| {
            (0..ring.len())
                .map(|i| (ring[i], ring[(i + 1) % ring.len()]))
                .collect()
        })
        .collect();

    // Rings that cannot touch cannot cut each other. Without this every ring
    // is tested against every other, which is the whole cost on a plan where
    // most walls are nowhere near each other.
    let boxes: Vec<Bounds> = inputs.iter().map(|r| Bounds::of(r)).collect();

    let mut out = Vec::new();
    for (i, edges) in edges_of.iter().enumerate() {
        let others: Vec<(Point, Point)> = edges_of
            .iter()
            .enumerate()
            .filter(|(j, _)| *j != i && boxes[i].overlaps(&boxes[*j]))
            .flat_map(|(_, e)| e.iter().copied())
            .collect();

        for &(a, b) in edges {
            if VertexKey::of(a) == VertexKey::of(b) {
                continue;
            }
            for w in cut_params(a, b, &others).windows(2) {
                let (p, q) = (lerp(a, b, w[0]), lerp(a, b, w[1]));
                if VertexKey::of(p) != VertexKey::of(q) {
                    out.push(Fragment {
                        owner: i,
                        from: p,
                        to: q,
                    });
                }
            }
        }
    }
    out
}

/// An axis-aligned bounding box, used only to reject pairs that cannot
/// interact before any exact predicate runs.
#[derive(Debug, Clone, Copy)]
struct Bounds {
    min_x: f64,
    min_y: f64,
    max_x: f64,
    max_y: f64,
}

impl Bounds {
    fn of(ring: &[Point]) -> Self {
        let mut b = Self {
            min_x: f64::INFINITY,
            min_y: f64::INFINITY,
            max_x: f64::NEG_INFINITY,
            max_y: f64::NEG_INFINITY,
        };
        for p in ring {
            b.min_x = b.min_x.min(p.x);
            b.min_y = b.min_y.min(p.y);
            b.max_x = b.max_x.max(p.x);
            b.max_y = b.max_y.max(p.y);
        }
        b
    }

    /// Overlap is tested with a weld-width margin, so two rings that only
    /// TOUCH — the normal case for a wall meeting a join patch — are never
    /// rejected by a boundary comparison that rounding could tip either way.
    fn overlaps(&self, other: &Self) -> bool {
        self.min_x <= other.max_x + WELD_MM
            && other.min_x <= self.max_x + WELD_MM
            && self.min_y <= other.max_y + WELD_MM
            && other.min_y <= self.max_y + WELD_MM
    }

    fn contains(&self, p: Point) -> bool {
        p.x >= self.min_x - WELD_MM
            && p.x <= self.max_x + WELD_MM
            && p.y >= self.min_y - WELD_MM
            && p.y <= self.max_y + WELD_MM
    }
}

/// Applies the three boundary rules and returns the surviving directed edges.
fn classify_fragments(inputs: &[Vec<Point>], fragments: &[Fragment]) -> Vec<(Point, Point)> {
    let mut directed: HashSet<(VertexKey, VertexKey)> = HashSet::new();
    for f in fragments {
        directed.insert((VertexKey::of(f.from), VertexKey::of(f.to)));
    }

    let boxes: Vec<Bounds> = inputs.iter().map(|r| Bounds::of(r)).collect();
    let mut emitted: HashSet<(VertexKey, VertexKey)> = HashSet::new();
    let mut kept = Vec::new();

    for f in fragments {
        let key = (VertexKey::of(f.from), VertexKey::of(f.to));
        // Rule 1: a reversed twin means interior on both sides.
        if directed.contains(&(key.1, key.0)) {
            continue;
        }
        // Rule 3 (dedupe): identical direction from two polygons is one edge.
        if emitted.contains(&key) {
            continue;
        }
        // Rule 2: strictly inside any other polygon.
        let mid = Point::new((f.from.x + f.to.x) / 2.0, (f.from.y + f.to.y) / 2.0);
        let swallowed = inputs.iter().enumerate().any(|(j, ring)| {
            j != f.owner
                && boxes[j].contains(mid)
                && classify_point(mid, ring) == Containment::Inside
        });
        if swallowed {
            continue;
        }
        emitted.insert(key);
        kept.push((f.from, f.to));
    }
    kept
}

/// Walks the surviving directed edges into closed rings.
fn trace_rings(edges: &[(Point, Point)]) -> Vec<Vec<Point>> {
    let mut position: HashMap<VertexKey, Point> = HashMap::new();
    let mut outgoing: HashMap<VertexKey, Vec<VertexKey>> = HashMap::new();
    for &(a, b) in edges {
        let (ka, kb) = (VertexKey::of(a), VertexKey::of(b));
        position.entry(ka).or_insert(a);
        position.entry(kb).or_insert(b);
        outgoing.entry(ka).or_default().push(kb);
        outgoing.entry(kb).or_default();
    }

    // Deterministic start order: HashMap iteration order must never reach the
    // output, or the same document renders a different component sequence
    // between runs.
    let mut starts: Vec<(VertexKey, VertexKey)> = edges
        .iter()
        .map(|&(a, b)| (VertexKey::of(a), VertexKey::of(b)))
        .collect();
    starts.sort();
    starts.dedup();

    let total = starts.len();
    let mut visited: HashSet<(VertexKey, VertexKey)> = HashSet::new();
    let mut rings = Vec::new();

    for start in starts {
        if visited.contains(&start) {
            continue;
        }
        let mut ring_keys = Vec::new();
        let (mut from, mut to) = start;

        loop {
            if !visited.insert((from, to)) {
                break;
            }
            ring_keys.push(from);
            let Some(next) = next_clockwise(&outgoing, &position, from, to) else {
                break;
            };
            from = to;
            to = next;
            if (from, to) == start {
                break;
            }
            // A ring cannot use more half-edges than exist; this bounds the
            // walk against a malformed adjacency rather than hanging.
            if ring_keys.len() > total {
                break;
            }
        }

        if ring_keys.len() >= 3 {
            rings.push(ring_keys.iter().map(|k| position[k]).collect());
        }
    }
    rings
}

/// The DCEL `next` rule: from the edge `from → to`, the continuation is the
//! Wall solids, join patches, occupied regions, and room faces.
//!
//! This module implements BEHAVIOR-SPEC R3.2 (derived occupied geometry) and
//! R5.1 (room topology) directly:
//!
//! - R3.2.1 — the occupied region is the union of every wall's centred
//!   butt-capped rectangle and one patch per join.
//! - R3.2.2 — at a join member endpoint, a wall contributes its cross-section:
//!   the closed segment of length `thicknessMm`, centred on the endpoint,
//!   perpendicular to that wall's own axis.
//! - R3.2.3 — the join patch is the CONVEX HULL of the member cross-sections.
//!   The specification is explicit that patches "need no miter construction
//!   and carry no miter-ratio constant", so no miter appears here.
//! - R5.1.1/R5.1.2 — a room is a bounded connected component of the complement
//!   of the occupied region, which is exactly a hole of a region component.
//!
//! Because rooms are complement components, floor area is measured to the
//! INNER faces of the walls. That is the difference between the area a person
//! can furnish and the area enclosed by the wall centre lines, and for a small
//! flat with 200 mm walls it is several square metres.

/// A wall reduced to what plan geometry needs: an axis and a thickness.
///
/// Height is deliberately absent. R3.0.6: "Height affects vertical extrusion
/// only: it never influences plan contact, splitting, joining, or derived
/// occupied geometry, so walls of unequal heights join in plan."
///
/// Coordinates and thickness are millimetres.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct WallSolid {
    /// Axis start.
    pub start: Point,
    /// Axis end.
    pub end: Point,
    /// Full thickness; the rectangle offsets half of it to each side.
    pub thickness_mm: f64,
}

impl WallSolid {
    /// Creates a wall solid.
    pub fn new(start: Point, end: Point, thickness_mm: f64) -> Self {
        Self {
            start,
            end,
            thickness_mm,
        }
    }

    /// The centred butt-capped rectangle of R3.0.2/R3.0.3, counter-clockwise.
    ///
    /// `None` for a zero-length axis, which R3.0.5 rejects as a wall.
    pub fn rectangle(&self) -> Option<[Point; 4]> {
        wall_polygon(self.start, self.end, self.thickness_mm)
    }

    /// Axis length in millimetres.
    pub fn length_mm(&self) -> f64 {
        (self.end.x - self.start.x).hypot(self.end.y - self.start.y)
    }
}

/// A join: at least two wall endpoints meeting at one point (R3.3.1).
///
/// Joins store no coordinates of their own; the node position is whatever the
/// member endpoints agree on (R3.3.4).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct JoinSpec {
    /// The participating wall endpoints, order irrelevant.
    pub members: Vec<JoinMember>,
}

/// The cross-section a wall contributes at one of its endpoints (R3.2.2).
///
/// The returned pair is the two ends of a closed segment of length
/// `thickness_mm`, centred on the endpoint and perpendicular to the wall axis.
/// `None` when the axis has zero length and has no perpendicular.
pub fn cross_section(wall: &WallSolid, endpoint: Endpoint) -> Option<[Point; 2]> {
    let (at, away) = match endpoint {
        Endpoint::Start => (wall.start, wall.end),
        Endpoint::End => (wall.end, wall.start),
    };
    let (dx, dy) = (away.x - at.x, away.y - at.y);
    let len = dx.hypot(dy);
    if !len.is_finite() || len == 0.0 {
        return None;
    }
    let half = wall.thickness_mm / 2.0;
    let (nx, ny) = (-dy / len * half, dx / len * half);
    Some([
        Point::new(at.x + nx, at.y + ny),
        Point::new(at.x - nx, at.y - ny),
    ])
}

/// The patch filling a join: the convex hull of its members' cross-sections
/// (R3.2.3).
///
/// Returns the hull vertices counter-clockwise. When every contributed point
/// is collinear — a straight continuation, fixture F3 — the hull degenerates
/// to the two extremes of a closed segment; the caller unions it as a closed
/// set, and since every cross-section is centred on the shared node, that
/// segment always lies within the thickest member's own rectangle.
pub fn join_patch(walls: &[WallSolid], join: &JoinSpec) -> Vec<Point> {
    let mut points = Vec::with_capacity(join.members.len() * 2);
    for m in &join.members {
        let Some(wall) = walls.get(m.wall) else {
            continue;
        };
        if let Some(cs) = cross_section(wall, m.endpoint) {
            points.extend_from_slice(&cs);
        }
    }
    convex_hull(&points)
}

/// The occupied region of a set of walls and their joins (R3.2.1).
///
/// The result is a canonical, deterministically ordered multipolygon; it may
/// be disconnected, and components may carry holes. Walls of unequal height
/// join in plan (R3.0.6) because height is not an input here.
///
/// All walls passed in must belong to the SAME level: R3.0.6 and R5.1.1 make
/// levels non-interacting, and mixing them would fuse geometry that never
/// touches.
pub fn occupied_region(walls: &[WallSolid], joins: &[JoinSpec]) -> Vec<Polygon> {
    let mut rings: Vec<Vec<Point>> = Vec::with_capacity(walls.len() + joins.len());
    for wall in walls {
        if let Some(rect) = wall.rectangle() {
            rings.push(rect.to_vec());
        }
    }
    for join in joins {
        let patch = join_patch(walls, join);
        if patch.len() >= 3 {
            rings.push(patch);
        }
    }
    crate::boolean::union(&rings)
}

/// The rooms of a level: the bounded components of the complement of `region`
/// (R5.1.1, R5.1.2).
///
/// Every hole of the occupied region is one room, bounded by the inner faces
/// of the surrounding walls. A separate wall cluster standing inside such a
/// hole — an island in a courtyard — becomes a hole of that room (R5.1.4), so
/// its footprint is not counted as floor area.
///
/// Output is totally ordered by the R5.1.3 canonical comparison.
pub fn rooms(region: &[Polygon]) -> Vec<Polygon> {
    let mut out = Vec::new();

    for component in region {
        for hole in &component.holes {
            // The hole ring winds clockwise as a void; as a room boundary it
            // is an exterior ring and must wind counter-clockwise.
            let outer: Vec<Point> = hole.iter().rev().copied().collect();

            // Islands standing in this room. Only the IMMEDIATE ones: an
            // island inside another island's own courtyard belongs to that
            // courtyard, and charging it here would subtract it twice.
            let inside: Vec<&Polygon> = region
                .iter()
                .filter(|c| ring_contains_ring(&outer, &c.outer))
                .collect();
            let holes: Vec<Vec<Point>> = inside
                .iter()
                .filter(|c| {
                    !inside.iter().any(|other| {
                        !std::ptr::eq(*other, **c) && ring_contains_ring(&other.outer, &c.outer)
                    })
                })
                .map(|c| c.outer.clone())
                .collect();

            if let Some(room) = (Polygon { outer, holes }).canonicalize() {
                out.push(room);
            }
        }
    }

    out.sort_by(compare_polygons);
    out
}

/// Convenience: the rooms enclosed by `walls` and `joins` on one level.
pub fn rooms_of(walls: &[WallSolid], joins: &[JoinSpec]) -> Vec<Polygon> {
    rooms(&occupied_region(walls, joins))
}

//! Shared planar-arrangement primitives: vertex welding, segment splitting,
//! and point classification against a ring.
//!
//! These are the pieces every boolean or face-traversal routine needs before
//! it can reason about a set of segments as a graph. They live here rather
//! than inside one consumer because two of them existing in two copies is how
//! a fix lands in one and not the other.

use crate::{orientation, Orientation};
use domowik_format::Point;

/// Endpoints within this distance are treated as the same vertex.
///
/// One micrometre: far below any meaningful building dimension, far above
/// floating-point noise on millimetre coordinates.
pub const WELD_MM: f64 = 0.001;

/// A vertex identity that tolerates rounding.
///
/// Two points that quantize to the same key are the same graph vertex. This is
/// what lets an intersection computed along one segment and the same
/// intersection computed along another meet in the adjacency structure instead
/// of becoming two vertices a nanometre apart.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct VertexKey(pub i64, pub i64);

impl VertexKey {
    /// Quantizes `p` onto the weld grid.
    pub fn of(p: Point) -> Self {
        Self(
            (p.x / WELD_MM).round() as i64,
            (p.y / WELD_MM).round() as i64,
        )
    }
}

/// Where a point lies relative to a closed ring.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Containment {
    /// Strictly inside.
    Inside,
    /// Exactly on an edge or vertex.
    Boundary,
    /// Strictly outside.
    Outside,
}

/// Linear interpolation along `a → b`.
pub fn lerp(a: Point, b: Point, t: f64) -> Point {
    Point::new(a.x + (b.x - a.x) * t, a.y + (b.y - a.y) * t)
}

/// Parameter `t` along `a→b` at which it meets `c→d`, if they properly cross
/// or touch. `None` when they are parallel, collinear, or do not meet.
pub fn intersection_param(a: Point, b: Point, c: Point, d: Point) -> Option<f64> {
    // Use the robust predicate to decide whether a crossing exists at all,
    // before computing where. Straddling on both sides is the crossing test.
    let (o1, o2) = (orientation(a, b, c), orientation(a, b, d));
    let (o3, o4) = (orientation(c, d, a), orientation(c, d, b));

    let proper = o1 != o2 && o3 != o4;
    let touching = o1 == Orientation::Collinear
        || o2 == Orientation::Collinear
        || o3 == Orientation::Collinear
        || o4 == Orientation::Collinear;

    if !proper && !touching {
        return None;
    }

    let (r1, r2) = (b.x - a.x, b.y - a.y);
    let (s1, s2) = (d.x - c.x, d.y - c.y);
    let denom = r1 * s2 - r2 * s1;
    if denom == 0.0 {
        // Parallel or collinear: no single crossing parameter.
        return None;
    }
    let t = ((c.x - a.x) * s2 - (c.y - a.y) * s1) / denom;
    let u = ((c.x - a.x) * r2 - (c.y - a.y) * r1) / denom;

    if (0.0..=1.0).contains(&t) && (0.0..=1.0).contains(&u) {
        Some(t)
    } else {
        None
    }
}

/// Parameters along `a→b` at which a COLLINEAR overlapping segment `c→d`
/// starts or ends.
///
/// [`intersection_param`] returns `None` for collinear input because there is
/// no single crossing point. That is correct as far as it goes, but on its own
/// it leaves overlapping segments unsplit: two collinear walls sharing part of
/// their length produce duplicate edges over the shared span, which corrupts
/// the angular adjacency and destroys the face walk. Overlapping walls are a
/// normal result of editing, so this is not an exotic case.
pub fn collinear_overlap_params(a: Point, b: Point, c: Point, d: Point) -> Vec<f64> {
    // Only meaningful when all four points are collinear.
    if orientation(a, b, c) != Orientation::Collinear
        || orientation(a, b, d) != Orientation::Collinear
    {
        return Vec::new();
    }
    let (rx, ry) = (b.x - a.x, b.y - a.y);
    let len2 = rx * rx + ry * ry;
    if len2 == 0.0 {
        return Vec::new();
    }
    // Project c and d onto a→b as parameters.
    [c, d]
        .iter()
        .map(|p| ((p.x - a.x) * rx + (p.y - a.y) * ry) / len2)
        .filter(|t| *t > 0.0 && *t < 1.0)
        .collect()
}

/// Every cut parameter along `a→b` induced by the segments in `others`.
///
/// The returned vector always begins at `0.0`, ends at `1.0`, is sorted, and
/// has near-duplicates collapsed, so `windows(2)` yields the sub-edges
/// directly.
pub fn cut_params(a: Point, b: Point, others: &[(Point, Point)]) -> Vec<f64> {
    let mut cuts: Vec<f64> = vec![0.0, 1.0];
    for &(c, d) in others {
        if VertexKey::of(c) == VertexKey::of(d) {
            continue;
        }
        if let Some(t) = intersection_param(a, b, c, d) {
            if t > 0.0 && t < 1.0 {
                cuts.push(t);
            }
        }
        cuts.extend(collinear_overlap_params(a, b, c, d));
    }
    cuts.sort_by(|x, y| x.partial_cmp(y).unwrap_or(std::cmp::Ordering::Equal));
    cuts.dedup_by(|x, y| (*x - *y).abs() < 1e-12);
    cuts
}

/// Classifies `p` against the closed ring `ring`.
///
/// The boundary test uses the exact orientation predicate, so a point lying on
/// an edge is reported as [`Containment::Boundary`] rather than falling to
/// whichever side rounding prefers. The interior test is the standard
/// crossing-number rule, evaluated only after the boundary case is excluded.
pub fn classify_point(p: Point, ring: &[Point]) -> Containment {
    if ring.len() < 3 {
        return Containment::Outside;
    }
    let n = ring.len();

    for i in 0..n {
        let (a, b) = (ring[i], ring[(i + 1) % n]);
        if orientation(a, b, p) == Orientation::Collinear
            && p.x >= a.x.min(b.x)
            && p.x <= a.x.max(b.x)
            && p.y >= a.y.min(b.y)
            && p.y <= a.y.max(b.y)
        {
            return Containment::Boundary;
        }
    }

    // Crossing number along the ray y = p.y, x > p.x. The half-open rule on
    // the vertical span (`a.y > p.y` differs from `b.y > p.y`) counts a vertex
    // exactly once when the ray passes through it.
    let mut inside = false;
    for i in 0..n {
        let (a, b) = (ring[i], ring[(i + 1) % n]);
        if (a.y > p.y) != (b.y > p.y) {
            let x = a.x + (p.y - a.y) / (b.y - a.y) * (b.x - a.x);
            if x > p.x {
                inside = !inside;
            }
        }
    }
    if inside {
        Containment::Inside
    } else {
        Containment::Outside
    }
}

/// True when every vertex of `inner` is inside or on `outer`, and at least one
/// is strictly inside.
///
/// Written for rings that are known not to cross — the arrangement has already
/// split every crossing — so vertex containment settles ring containment.
pub fn ring_contains_ring(outer: &[Point], inner: &[Point]) -> bool {
    let mut any_strictly_inside = false;
    for &p in inner {
        match classify_point(p, outer) {
            Containment::Outside => return false,
            Containment::Inside => any_strictly_inside = true,
            Containment::Boundary => {}
        }
    }
    any_strictly_inside
}

        );
    }

    53	/// Parameter `t` along `a→b` at which it meets `c→d`, if they properly cross
    54	/// or touch. `None` when they are parallel, collinear, or do not meet.
    55	pub fn intersection_param(a: Point, b: Point, c: Point, d: Point) -> Option<f64> {
    56	    // Use the robust predicate to decide whether a crossing exists at all,
    57	    // before computing where. Straddling on both sides is the crossing test.
    58	    let (o1, o2) = (orientation(a, b, c), orientation(a, b, d));
    59	    let (o3, o4) = (orientation(c, d, a), orientation(c, d, b));
    60	
    61	    let proper = o1 != o2 && o3 != o4;
    62	    let touching = o1 == Orientation::Collinear
    63	        || o2 == Orientation::Collinear
    64	        || o3 == Orientation::Collinear
    65	        || o4 == Orientation::Collinear;
    66	
    67	    if !proper && !touching {
    68	        return None;
    69	    }
    70	
    71	    let (r1, r2) = (b.x - a.x, b.y - a.y);
    72	    let (s1, s2) = (d.x - c.x, d.y - c.y);
    73	    let denom = r1 * s2 - r2 * s1;
    74	    if denom == 0.0 {
    75	        // Parallel or collinear: no single crossing parameter.
    76	        return None;
    77	    }
    78	    let t = ((c.x - a.x) * s2 - (c.y - a.y) * s1) / denom;
    79	    let u = ((c.x - a.x) * r2 - (c.y - a.y) * r1) / denom;
    80	
    81	    if (0.0..=1.0).contains(&t) && (0.0..=1.0).contains(&u) {
    82	        Some(t)
    83	    } else {
    84	        None
    85	    }
    86	}

    88	/// Parameters along `a→b` at which a COLLINEAR overlapping segment `c→d`
    89	/// starts or ends.
    90	///
    91	/// [`intersection_param`] returns `None` for collinear input because there is
    92	/// no single crossing point. That is correct as far as it goes, but on its own
    93	/// it leaves overlapping segments unsplit: two collinear walls sharing part of
    94	/// their length produce duplicate edges over the shared span, which corrupts
    95	/// the angular adjacency and destroys the face walk. Overlapping walls are a
    96	/// normal result of editing, so this is not an exotic case.
    97	pub fn collinear_overlap_params(a: Point, b: Point, c: Point, d: Point) -> Vec<f64> {
    98	    // Only meaningful when all four points are collinear.
    99	    if orientation(a, b, c) != Orientation::Collinear
   100	        || orientation(a, b, d) != Orientation::Collinear
   101	    {
   102	        return Vec::new();
   103	    }
   104	    let (rx, ry) = (b.x - a.x, b.y - a.y);
   105	    let len2 = rx * rx + ry * ry;
   106	    if len2 == 0.0 {
   107	        return Vec::new();
   108	    }
   109	    // Project c and d onto a→b as parameters.
   110	    [c, d]
   111	        .iter()
   112	        .map(|p| ((p.x - a.x) * rx + (p.y - a.y) * ry) / len2)
   113	        .filter(|t| *t > 0.0 && *t < 1.0)
   114	        .collect()
   115	}

   117	/// Every cut parameter along `a→b` induced by the segments in `others`.
   118	///
   119	/// The returned vector always begins at `0.0`, ends at `1.0`, is sorted, and
   120	/// has near-duplicates collapsed, so `windows(2)` yields the sub-edges
   121	/// directly.
   122	pub fn cut_params(a: Point, b: Point, others: &[(Point, Point)]) -> Vec<f64> {
   123	    let mut cuts: Vec<f64> = vec![0.0, 1.0];
   124	    for &(c, d) in others {
   125	        if VertexKey::of(c) == VertexKey::of(d) {
   126	            continue;
   127	        }
   128	        if let Some(t) = intersection_param(a, b, c, d) {
   129	            if t > 0.0 && t < 1.0 {
   130	                cuts.push(t);
   131	            }
   132	        }
   133	        cuts.extend(collinear_overlap_params(a, b, c, d));
   134	    }
   135	    cuts.sort_by(|x, y| x.partial_cmp(y).unwrap_or(std::cmp::Ordering::Equal));
   136	    cuts.dedup_by(|x, y| (*x - *y).abs() < 1e-12);
   137	    cuts
   138	}

   140	/// Classifies `p` against the closed ring `ring`.
   141	///
   142	/// The boundary test uses the exact orientation predicate, so a point lying on
   143	/// an edge is reported as [`Containment::Boundary`] rather than falling to
   144	/// whichever side rounding prefers. The interior test is the standard
   145	/// crossing-number rule, evaluated only after the boundary case is excluded.
   146	pub fn classify_point(p: Point, ring: &[Point]) -> Containment {
   147	    if ring.len() < 3 {
   148	        return Containment::Outside;
   149	    }
   150	    let n = ring.len();
   151	
   152	    for i in 0..n {
   153	        let (a, b) = (ring[i], ring[(i + 1) % n]);
   154	        if orientation(a, b, p) == Orientation::Collinear
   155	            && p.x >= a.x.min(b.x)
   156	            && p.x <= a.x.max(b.x)
   157	            && p.y >= a.y.min(b.y)
   158	            && p.y <= a.y.max(b.y)
   159	        {
   160	            return Containment::Boundary;
   161	        }
   162	    }
   163	
   164	    // Crossing number along the ray y = p.y, x > p.x. The half-open rule on
   165	    // the vertical span (`a.y > p.y` differs from `b.y > p.y`) counts a vertex
   166	    // exactly once when the ray passes through it.
   167	    let mut inside = false;
   168	    for i in 0..n {
   169	        let (a, b) = (ring[i], ring[(i + 1) % n]);
   170	        if (a.y > p.y) != (b.y > p.y) {
   171	            let x = a.x + (p.y - a.y) / (b.y - a.y) * (b.x - a.x);
   172	            if x > p.x {
   173	                inside = !inside;
   174	            }
   175	        }
   176	    }
   177	    if inside {
   178	        Containment::Inside
   179	    } else {
   180	        Containment::Outside
   181	    }
   182	}

   184	/// True when every vertex of `inner` is inside or on `outer`, and at least one
   185	/// is strictly inside.

   188	/// split every crossing — so vertex containment settles ring containment.

   190	    let mut any_strictly_inside = false;

   195	            Containment::Boundary => {}
   196	        }
   197	    }
   198	    any_strictly_inside
   199	}

### 3. `rooms` misses a room enclosed collectively by point-touching components

Input rings:

```text
T1 = [
  (0, 0),
  (5, 0),
  (0, 5)

T2 = [
  (5, 0),
  (10, 0),
  (10, 5)

  (10, 5),

  (5, 10),
  (0, 10),
  (0, 5)

```

Let:

```text
region = union([T1, T2, T3, T4])
```

The four occupied triangles meet cyclically at `(5,0)`, `(10,5)`, `(5,10)`, and `(0,5)`. Their union contains the entire outer square boundary, so the complement has one bounded component:

```text
room.outer = [
  (5, 0),
  (10, 5),
  (5, 10),
  (0, 5)
]
room.holes = []
room area = 50
```

The code produces four triangle polygons with no holes, followed by:

```text
rooms(region) = []
```

Why: at every degree-four pinch, the clockwise continuation at [boolean.rs:269](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-geometry/src/boolean.rs:269) stays on the boundary of the same triangle. That is locally consistent with the stated pinch rule, but it never traces the clockwise diamond boundary assembled from edges belonging to four different components.

Then [walls.rs:176](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-geometry/src/walls.rs:176) examines only holes already attached to individual `Polygon` components. The bounded diamond complement is not a hole of any one triangle, so it is invisible. The assertion at [walls.rs:167](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-geometry/src/walls.rs:167) that every room is a hole of an occupied-region component is false when components form a point-contact cycle.

The union’s represented set is correct in this example; the failure is specifically in deriving complement components from per-polygon holes.

### 4. Welded vertex coordinates depend on input order

Input squares:

```text
A = [
  (0, 0),
  (1, 0),
  (1, 1),
  (0, 1)
]

B = [
  (1.0004, 1.0004),
  (2, 1.0004),
  (2, 2),
  (1.0004, 2)
]
```

They are disjoint, including at their nearest corners. Correct output is the two unchanged squares regardless of input order.

For `union([A, B])`, the code produces:

```text
[
  [(0,0), (1,0), (1,1), (0,1)],
  [(1,1), (2,1.0004), (2,2), (1.0004,2)]
]
```

For `union([B, A])`, it produces:

```text
[
  [(0,0), (1,0), (1.0004,1.0004), (0,1)],
  [(1.0004,1.0004), (2,1.0004), (2,2), (1.0004,2)]
]
```

Thus one polygon acquires the other polygon’s corner. The total areas also differ: approximately `1.9996` versus `1.99960016`, while the correct total is `1.99920016`.

Why: the two distinct corners receive the same `VertexKey`. At [boolean.rs:206](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-geometry/src/boolean.rs:206), `position.entry(key).or_insert(point)` keeps whichever physical coordinate occurs first. The result therefore depends on ring order.

This is not HashMap iteration nondeterminism; it is deterministic first-writer-wins behavior with an order-dependent writer.

## Verification and assessment of the suggested areas

- **Three-or-more nested overlap:** I could not break the midpoint rule solely through nesting. Once splitting is complete, membership in any other ring is sufficient to make that fragment internal to the union. Whether that other ring is itself inside a third ring is irrelevant. Finding 1 breaks the prerequisite—complete splitting—not the membership logic.

- **Three rings sharing one exact edge:** sound. If all three directions agree, retaining one copy is correct. If either direction is represented, there is occupied interior on both sides, so dropping every copy is correct. Finding 2 shows that the implementation can falsely identify nearby, noncoincident edges as twins.

- **Degree-four vertices:** the clockwise rule correctly separates an isolated point-touch into distinct occupied rings. It is not sufficient for room discovery when several such contacts form a cycle; Finding 3 is the concrete failure.

- **A hole touching its outer at one point:** I did not find an independent failure. If any other hole vertex is strictly inside, `ring_contains_ring` accepts it, and the clockwise traversal can separate the outer and hole cycles.

- **Every vertex shared:** `ring_contains_ring` deliberately returns false when every inner vertex is on the boundary at [arrangement.rs:189](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-geometry/src/arrangement.rs:189). That is not a generally valid ring-containment predicate, but I could not ground an additional valid `union` output where this alone causes the wrong result. Coincident opposite boundaries are normally eliminated earlier.

- **Zero-area/sliver rings:** signed-zero traced rings are dropped at [boolean.rs:309](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-geometry/src/boolean.rs:309). I could not assess `canonical_ring` itself without violating the three-file restriction. Finding 1 does demonstrate a nonzero exposed strip being lost through parameter-space sliver deduplication.

- **Hash iteration:** no direct run-to-run HashMap/HashSet iteration leak was found. Starts are explicitly sorted, and maps are otherwise queried by key. Input-order determinism is nevertheless false because of Finding 4.
