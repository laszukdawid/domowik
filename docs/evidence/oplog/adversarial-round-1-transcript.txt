//! The operation log: framing validation, causal holding, and canonical order.
//!
//! Implements FORMAT-SPEC §4.3 row 4 (framing rejects, BEFORE replay), §4.4
//! (frontier, delivery-order independence) and §4.5 I2 (duplicate suppression).
//!
//! **This is not a CRDT** (§4 preamble). The log provides replay and
//! synchronization metadata only; §4.6's conflict rule is deterministic
//! per-field last-writer-wins and is LOSSY. Nothing here provides convergence.

use crate::operation::Batch;
use std::collections::{BTreeMap, HashMap, HashSet};
use thiserror::Error;
use uuid::Uuid;

/// Why a batch could not enter the log.
///
/// Every variant is a §4.3 row 4 framing anomaly: rejected BEFORE replay
/// begins, never partially applied.
#[derive(Debug, Error, PartialEq)]
pub enum LogError {
    #[error("batch {batch_id} has no operations; an empty batch defines an empty counter range and no frontier position (FORMAT-SPEC B3)")]
    EmptyBatch { batch_id: Uuid },

    #[error("batch {batch_id} declares counterBase {counter_base}; an actor's counter starts at 1 (FORMAT-SPEC B3)")]
    CounterBaseBelowOne { batch_id: Uuid, counter_base: u64 },

    #[error("batch {batch_id}: frontier member {actor} has counter zero; absence is the sole spelling of nothing observed (FORMAT-SPEC F1 zero prohibition)")]
    ZeroFrontierMember { batch_id: Uuid, actor: Uuid },

    #[error("batch {batch_id} is already in the log with different content; batch ids are unique (FORMAT-SPEC E1)")]
    DuplicateBatchId { batch_id: Uuid },

    #[error("batch {batch_id} reserves counters {from}..={to} for actor {actor}, overlapping a range already reserved")]
    OverlappingRange {
        batch_id: Uuid,
        actor: Uuid,
        from: u64,
        to: u64,
    },

    #[error("batch {batch_id} starts actor {actor} at counter {from}, leaving a gap after {expected}; an actor's ranges are contiguous with no gaps (FORMAT-SPEC B3)")]
    CounterGap {
        batch_id: Uuid,
        actor: Uuid,
        from: u64,
        expected: u64,
    },
}

/// What happened to a delivered batch.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Delivery {
    /// Accepted and now part of the log.
    Accepted,
    /// Its whole counter range lies at or below the watermark: already
    /// applied, ignored silently and deterministically (§4.5 I2).
    Duplicate,
    /// Causal prerequisites are not yet present; held until they arrive (F3).
    Held,
}

/// A durable log of operation batches.
///
/// Batches may arrive in any order (F3). The log holds a batch whose causal
/// prerequisites are absent and promotes it when they arrive, so the projected
/// result is a function of the delivered SET and never of arrival sequence.
#[derive(Debug, Clone, Default)]
pub struct OperationLog {
    accepted: Vec<Batch>,
    held: Vec<Batch>,
    ids: HashSet<Uuid>,
    /// actor → highest counter accepted, the per-actor watermark.
    watermark: HashMap<Uuid, u64>,
    /// actor → counter covered by the baseline snapshot, if any.
    baseline: HashMap<Uuid, u64>,
}

impl OperationLog {
    pub fn new() -> Self {
        Self::default()
    }

    /// A log that continues from a snapshot's frontier (FORMAT-SPEC §5.1 S2).
    ///
    /// The frontier states which counters the snapshot already covers, so the
    /// log can tell a batch that is ALREADY APPLIED (I2, at or below the
    /// watermark) from one whose predecessors have not arrived (F3, held).
    /// Without it a snapshot-seeded log holds every subsequent batch forever,
    /// because their prerequisites were compacted away.
    ///
    /// A zero-valued member is rejected here as it is anywhere else (F1); an
    /// invalid seed would silently become watermark state, which F1 forbids
    /// specifically.
    pub fn with_baseline_frontier(frontier: &BTreeMap<Uuid, u64>) -> Result<Self, LogError> {
        let mut log = Self::default();
        for (&actor, &counter) in frontier {
            if counter == 0 {
                return Err(LogError::ZeroFrontierMember {
                    batch_id: Uuid::nil(),
                    actor,
                });
            }
            log.watermark.insert(actor, counter);
            log.baseline.insert(actor, counter);
        }
        Ok(log)
    }

    /// The frontier a snapshot of the current state should record (S2).
    pub fn baseline_frontier(&self) -> BTreeMap<Uuid, u64> {
        self.frontier()
    }

    /// The baseline frontier this log was SEEDED with, for rebuilding it.
    pub fn baseline_frontier_seed(&self) -> BTreeMap<Uuid, u64> {
        self.baseline.iter().map(|(&a, &c)| (a, c)).collect()
    }

    /// Batches accepted so far, in arrival order.
    pub fn batches(&self) -> &[Batch] {
        &self.accepted
    }

    /// Batches held for missing causal prerequisites (F3).
    pub fn held(&self) -> &[Batch] {
        &self.held
    }

    /// The per-actor watermark: highest counter accepted for each actor.
    pub fn watermark(&self) -> &HashMap<Uuid, u64> {
        &self.watermark
    }

    /// The frontier a new local batch should declare: everything observed.
    pub fn frontier(&self) -> BTreeMap<Uuid, u64> {
        self.watermark
            .iter()
            .filter(|(_, &c)| c > 0)
            .map(|(&a, &c)| (a, c))
            .collect()
    }

    /// The next unused counter for `actor`.
    pub fn next_counter(&self, actor: Uuid) -> u64 {
        self.watermark.get(&actor).copied().unwrap_or(0) + 1
    }

    /// Delivers a batch.
    ///
    /// Framing is checked BEFORE anything else, because §4.3 row 4 rejects
    /// framing anomalies before replay begins and I2 explicitly does not
    /// exempt a duplicate from them: "watermark classification never precedes,
    /// gates, or replaces the pre-replay structural checks".
    pub fn deliver(&mut self, batch: Batch) -> Result<Delivery, LogError> {
        self.check_framing(&batch)?;

        // I2: a range wholly at or below the watermark is already applied.
        let mark = self.watermark.get(&batch.actor_id).copied().unwrap_or(0);
        if batch.range_end() <= mark {
            return Ok(Delivery::Duplicate);
        }

        if !self.prerequisites_present(&batch) {
            self.held.push(batch);
            return Ok(Delivery::Held);
        }

        self.accept(batch);
        self.promote_held();
        Ok(Delivery::Accepted)
    }

    fn accept(&mut self, batch: Batch) {
        self.ids.insert(batch.batch_id);
        let end = batch.range_end();
        let mark = self.watermark.entry(batch.actor_id).or_insert(0);
        *mark = (*mark).max(end);
        self.accepted.push(batch);
    }

    /// Re-checks held batches after an acceptance, repeatedly, because
    /// promoting one can satisfy another's prerequisites.
    fn promote_held(&mut self) {
        loop {
            let Some(i) = self.held.iter().position(|b| self.prerequisites_present(b)) else {
                return;
            };
            let batch = self.held.remove(i);
            // A batch can become a duplicate while held, if the same range
            // arrived by another route.
            let mark = self.watermark.get(&batch.actor_id).copied().unwrap_or(0);
            if batch.range_end() > mark {
                self.accept(batch);
            }
        }
    }

    /// F3: a batch whose frontier points at batches not yet present is held.
    ///
    /// Because B3 makes each actor's ranges contiguous from 1, "every batch
    /// its frontier points to is present" reduces to "the watermark for each
    /// frontier actor is at least the counter the frontier names" — the
    /// contiguity is what makes the watermark a complete answer rather than a
    /// high-water mark with holes under it.
    ///
    /// A batch's own actor is exempt for its own prior counters: those are
    /// checked by the gap rule in [`Self::check_framing`], which reports a
    /// missing predecessor as the framing anomaly it is rather than holding
    /// forever.
    fn prerequisites_present(&self, batch: &Batch) -> bool {
        let observed = batch
            .frontier
            .iter()
            .all(|(&actor, &counter)| self.watermark.get(&actor).copied().unwrap_or(0) >= counter);
        // B3 also makes an actor's OWN prior counters a prerequisite: a batch
        // at counterBase n needs 1..n-1 of that actor present, or the
        // watermark would advance over a hole.
        let mark = self.watermark.get(&batch.actor_id).copied().unwrap_or(0);
        observed && batch.counter_base <= mark + 1
    }

    fn check_framing(&self, batch: &Batch) -> Result<(), LogError> {
        if batch.operations.is_empty() {
            return Err(LogError::EmptyBatch {
                batch_id: batch.batch_id,
            });
        }
        if batch.counter_base < 1 {
            return Err(LogError::CounterBaseBelowOne {
                batch_id: batch.batch_id,
                counter_base: batch.counter_base,
            });
        }
        if let Some((&actor, _)) = batch.frontier.iter().find(|(_, &c)| c == 0) {
            return Err(LogError::ZeroFrontierMember {
                batch_id: batch.batch_id,
                actor,
            });
        }

        // A re-delivery of the SAME batch is a duplicate, not a collision; a
        // different batch reusing an accepted id is a framing anomaly.
        if self.ids.contains(&batch.batch_id)
            && !self
                .accepted
                .iter()
                .any(|b| b.batch_id == batch.batch_id && b == batch)
        {
            return Err(LogError::DuplicateBatchId {
                batch_id: batch.batch_id,
            });
        }

        // Duplicate reserved ranges and overlapping ranges are the same
        // §7.6 anomaly seen from two angles, and both are decided against the
        // ACCEPTED batches rather than against the watermark. A watermark test
        // alone cannot tell a re-delivery of a batch from a DIFFERENT batch
        // claiming the same counters: both sit at or below the mark, and only
        // the second is malformed.
        let (from, to) = batch.counter_range();
//! Replay: projecting an operation log into a document.
//!
//! Implements FORMAT-SPEC §4.5 (tombstones, the I5 three-branch staleness
//! test) and §4.6 (per-field last-writer-wins), by applying batches in the
//! canonical order §4.4 F3 defines.
//!
//! # Why applying in canonical order IS the conflict rule
//!
//! LWW1 says the winning write for a field is the one with the greatest write
//! position, and that this "is exactly the LAST write to that field in
//! canonical order". So there is no separate merge step: sort by position,
//! apply in order, and let a later write overwrite an earlier one. LWW3
//! (deletes dominate) falls out the same way — a canonically later delete
//! tombstones whatever a set wrote — and so does LWW4, where the surviving
//! create is simply the last one applied.
//!
//! What does NOT fall out, and is therefore explicit below, is I5: an
//! operation must be classified against its target's LIVE INTERVAL at its own
//! write position, not against the current projection. The two-way reading —
//! present-or-absent right now — makes I5's branch 2 indistinguishable from
//! branch 3 and silently changes an unrelated field's value.

use crate::log::OperationLog;
use crate::operation::{Batch, Operation, OperationKind, WritePosition};
use domowik_format::{Document, Entity};
use serde_json::Value;
use std::collections::HashMap;
use uuid::Uuid;

/// An entity's live interval (FORMAT-SPEC §4.5 I3).
///
/// `[creation_position, deleting_position)`. A tombstone keeps the interval so
/// deletion does not erase the fact that the entity once existed at a
/// position.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct LiveInterval {
    /// Write position of the create that opened the interval.
    pub created_at: WritePosition,
    /// Write position of the delete that closed it, if any.
    pub deleted_at: Option<WritePosition>,
    /// The actor whose delete closed it. Used for E6's authorized restoration.
    pub deleted_by: Option<Uuid>,
}

/// Where an operation's target stands at that operation's write position.
///
/// I5 classifies in exactly THREE ways rather than two. The third is the one a
/// present-or-absent test cannot express.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum TargetState {
    /// Branch 1: the target's creation is not earlier than this write.
    BeforeCreation,
    /// Branch 2: the target exists at this position.
    Live,
    /// Branch 3: the target's deletion is earlier than this write.
    AfterDeletion,
}

/// Why a batch was discarded during replay.
#[derive(Debug, Clone, PartialEq)]
pub struct Discard {
    pub batch_id: Uuid,
    pub operation_id: Uuid,
    pub entity_id: Uuid,
    pub reason: TargetState,
}

/// The result of replaying a log.
#[derive(Debug, Clone, Default)]
pub struct Projection {
    /// The authoritative document.
    pub document: Document,
    /// Live intervals, including closed ones (tombstones).
    pub intervals: HashMap<Uuid, LiveInterval>,
    /// Batches discarded as stale, in canonical order. A projection outcome,
    /// not an error: silent to end users, recorded here (I5).
    pub discarded: Vec<Discard>,
}

impl Projection {
    /// True when `id` has been created and not since deleted.
    pub fn is_live(&self, id: Uuid) -> bool {
        self.intervals
            .get(&id)
            .is_some_and(|i| i.deleted_at.is_none())
    }

    /// True when `id` carries a tombstone.
    pub fn is_tombstoned(&self, id: Uuid) -> bool {
        self.intervals
            .get(&id)
            .is_some_and(|i| i.deleted_at.is_some())
    }
}

/// Replays `log` into a projection.
pub fn project(log: &OperationLog) -> Projection {
    project_from(&Document::default(), log)
}

/// A write position that strictly precedes every valid one.
///
/// Valid batches have `counterBase >= 1` (B3), so `(0, 0, 0)` is below every
/// real position at the same causal past size and below every larger one. This
/// is what lets a baseline document's entities be LIVE for operations that
/// follow it without inventing a fake batch to have created them.
pub const BASELINE: WritePosition = WritePosition {
    batch: crate::operation::Position {
        causal_past_size: 0,
        counter_base: 0,
        actor: 0,
    },
    operation_index: 0,
};

/// Replays `log` on top of `baseline`.
///
/// `baseline` is a previously projected state — FORMAT-SPEC §5's snapshot
/// role. Its entities are seeded as live from [`BASELINE`], so a later
/// `setFields` finds its target within a live interval (I5 branch 2) rather
/// than before creation. Replaying `log` on top of the state `log`'s own
/// prefix produced must give the same answer as replaying the whole log, which
/// is vector V6's requirement.
///
/// Tombstones are NOT carried by a baseline document, because a document is a
/// set of live entities. A baseline therefore cannot block resurrection of
/// something deleted before it was taken; §5.1 S4 exists to carry tombstones
/// alongside a snapshot and is not implemented (issue 0027). Until it is, do
/// not use a baseline across a compaction that dropped a delete.
pub fn project_from(baseline: &Document, log: &OperationLog) -> Projection {
    let mut p = Projection {
        document: baseline.clone(),
        ..Projection::default()
    };
    for entity in baseline_ids(baseline) {
        p.intervals.insert(
            entity,
            LiveInterval {
                created_at: BASELINE,
                deleted_at: None,
                deleted_by: None,
            },
        );
    }
    for batch in log.canonical_order() {
        apply_batch(&mut p, batch);
    }
    p
}

fn baseline_ids(document: &Document) -> Vec<Uuid> {
    document
        .levels
        .iter()
        .map(|l| l.id)
        .chain(document.walls.iter().map(|w| w.id))
        .chain(document.openings.iter().map(|o| o.id))
        .chain(document.joins.iter().map(|j| j.id))
        .collect()
}

/// Applies one batch atomically, or discards it as stale (B1, I5).
///
/// The batch is classified against a SCRATCH copy so a discard leaves no trace:
/// atomicity forbids partial application, and "check everything first" is not
/// enough on its own because an operation may legitimately depend on an
/// earlier operation of the same batch (B4).
fn apply_batch(p: &mut Projection, batch: &Batch) {
    let mut document = p.document.clone();
    let mut intervals = p.intervals.clone();

    for (index, op) in batch.operations.iter().enumerate() {
        let at = batch.write_position(index);
        let state = classify(&intervals, op.entity_id, at);

        let stale = match &op.kind {
            // A create ESTABLISHES existence at its own position: it is never
            // stale for want of its own target. It is refused only against a
            // tombstone it is not authorized to restore.
            OperationKind::CreateEntity { .. } => {
                state == TargetState::AfterDeletion && !authorized_restore(&intervals, op, batch)
            }
            // A delete against a live target closes the interval; against an
            // absent or already-tombstoned target it is stale on the same
            // terms as branch 1 or branch 3.
            OperationKind::DeleteEntity => state != TargetState::Live,
            // The interval test governs operations REQUIRING a pre-existing
            // target, classified at that operation's own write position.
            OperationKind::SetFields { .. } => state != TargetState::Live,
        };

        if stale {
            p.discarded.push(Discard {
                batch_id: batch.batch_id,
                operation_id: op.operation_id,
                entity_id: op.entity_id,
                reason: state,
            });
            // If ANY operation is stale the WHOLE batch is discarded,
            // including operations whose own targets were live (B1).
            return;
        }

        apply_operation(&mut document, &mut intervals, op, at, batch.actor_id);
    }

    p.document = document;
    p.intervals = intervals;
}

/// I5's three-branch classification, evaluated at `at` rather than "now".
fn classify(intervals: &HashMap<Uuid, LiveInterval>, id: Uuid, at: WritePosition) -> TargetState {
    let Some(interval) = intervals.get(&id) else {
        return TargetState::BeforeCreation;
    };
    if interval.created_at >= at {
        return TargetState::BeforeCreation;
    }
    match interval.deleted_at {
        Some(d) if d < at => TargetState::AfterDeletion,
        _ => TargetState::Live,
    }
}

/// E6's sole reuse exception: authorized restoration of a tombstoned identity
/// by the same device's own undo (BEHAVIOR-SPEC R8.1.3).
///
/// Authorization is read from PROVENANCE rather than from a flag on the
/// operation: the restoring create is authorized exactly when the tombstone it
/// would reopen was written by the same actor. "Tombstones created by sync
/// merge are never resurrected" is then automatic, because a merged tombstone
/// carries another actor's id.
///
/// The limit of this reading, stated because it is a real one: within a single
/// actor stream it also permits a create of a tombstoned id that is NOT a
/// redo. Nothing downstream of the log can tell the two apart. §4.2 O4 puts
/// that check on the AUTHORING replica at command time, and
/// [`crate::session::Session`] is where it lives here — it mints a restoring
/// create only from its own redo stack.
fn authorized_restore(
    intervals: &HashMap<Uuid, LiveInterval>,
    op: &Operation,
    batch: &Batch,
) -> bool {
    intervals
        .get(&op.entity_id)
        .and_then(|i| i.deleted_by)
        .is_some_and(|by| by == batch.actor_id)
}

fn apply_operation(
    document: &mut Document,
    intervals: &mut HashMap<Uuid, LiveInterval>,
    op: &Operation,
    at: WritePosition,
    actor: Uuid,
) {
    match &op.kind {
        OperationKind::CreateEntity { entity } => {
            document.insert_entity(entity.clone());
            intervals.insert(
                op.entity_id,
                LiveInterval {
                    created_at: at,
                    deleted_at: None,
                    deleted_by: None,
                },
            );
        }
        OperationKind::SetFields { fields } => {
            if let Some(current) = document.entity(op.entity_id) {
                if let Some(updated) = merge_fields(&current, fields) {
                    document.insert_entity(updated);
                }
            }
        }
        OperationKind::DeleteEntity => {
            document.remove_entity(op.entity_id);
            if let Some(interval) = intervals.get_mut(&op.entity_id) {
                interval.deleted_at = Some(at);
                interval.deleted_by = Some(actor);
            }
        }
    }
}

/// Applies a `setFields` payload to an entity.
///
/// O3: fields are addressed by SERIALIZED NAME at top level, and set- or
/// array-valued fields are replaced WHOLESALE. Going through JSON is what
/// makes that literally true rather than approximately true — the payload
/// names the same strings the format writes, and no field is merged
/// element-wise because none is descended into.
///
/// Returns `None` when the result would not deserialize, which means the
/// payload named a field with an incompatible value. The operation then has no
/// effect; commit-time validation (O4) is what should have caught it, and
/// [`crate::session::Session`] runs it.
fn merge_fields(entity: &Entity, fields: &serde_json::Map<String, Value>) -> Option<Entity> {
    let mut value = serde_json::to_value(entity).ok()?;
    let object = value.as_object_mut()?;
    for (name, new) in fields {
        // `null` clears an optional field to absent (§4.2 O2). Every other
        // value replaces wholesale.
        if new.is_null() {
            object.remove(name);
        } else {
            object.insert(name.clone(), new.clone());
        }
    }
    serde_json::from_value(value).ok()
}

/// The `setFields` payload that would restore `entity`'s current values for
/// the field names `fields` names.
///
/// This is how an undo of a field edit is built: capture the prior values of
/// exactly the fields the forward operation touched. A field the forward
/// operation ADDED (absent before) is restored by `null`, which §4.2 O2
/// defines as clearing to absent.
//! The local command session: commands, undo, and redo.
//!
//! Implements BEHAVIOR-SPEC §8 (normative) and FORMAT-SPEC §4.8's boundary.
//!
//! # The shape of undo here, and why it is not a stack of old states
//!
//! R8.1.1: executing undo appends a NEW compensating batch built from inverse
//! effects. History grows monotonically and is never mutated or reordered, so
//! replay and synchronization metadata stay correct. R8.1.2: every executed
//! undo AND redo mints fresh operation and batch identities and advances the
//! actor counter — entries are never popped and reused.
//!
//! R8.1.3 is the one rule that reaches back into identity: redo restores the
//! SAME ENTITY ids its undone command created, including reopening a tombstone
//! this device's own undo wrote. Operation and batch ids are always fresh; only
//! entity ids are reused, and only under that authorization.

use crate::log::{Delivery, LogError, OperationLog};
use crate::operation::{Batch, Operation, OperationKind};
use crate::replay::{prior_values, project_from, Projection};
use domowik_format::{Document, ValidationError};
use std::collections::VecDeque;
use thiserror::Error;
use uuid::Uuid;

/// Why a command did not commit.
#[derive(Debug, Error)]
pub enum CommandError {
    /// The resulting document would be invalid. Rejected atomically BEFORE any
    /// effect, with no undo entry (FORMAT-SPEC §4.3 row 1, R8.2.2).
    #[error("command rejected: {}", .0.iter().map(|e| e.to_string()).collect::<Vec<_>>().join("; "))]
    Invalid(Vec<ValidationError>),
    /// The batch could not enter the log.
    #[error(transparent)]
    Framing(#[from] LogError),
    /// The batch was discarded as stale at its canonical position, or held.
    #[error("batch was not applied: {0}")]
    NotApplied(&'static str),
}

/// One entry on the undo or redo stack.
///
/// Holds both directions, because R8.1.2 forbids reusing the original batch:
/// undo emits `inverse` under fresh identities and redo emits `forward` under
/// fresh identities, and the entry moves between the stacks unchanged.
#[derive(Debug, Clone)]
struct StackEntry {
    forward: Vec<Operation>,
    inverse: Vec<Operation>,
}

impl StackEntry {
    /// A copy with freshly minted operation ids, preserving ENTITY ids.
    ///
    /// R8.1.2 and R8.1.3 together: operation identity is always new, entity
    /// identity is deliberately reused.
    fn refreshed(ops: &[Operation]) -> Vec<Operation> {
        ops.iter()
            .map(|op| Operation {
                operation_id: Uuid::now_v7(),
                entity_id: op.entity_id,
                kind: op.kind.clone(),
            })
            .collect()
    }
}

/// Default capacities. R8.4.4 makes the EXISTENCE of a bound normative and the
/// values implementation policy; these are ours, and they are independent.
pub const DEFAULT_UNDO_CAPACITY: usize = 200;
pub const DEFAULT_REDO_CAPACITY: usize = 200;

/// An open document on one device.
///
/// Owns the durable log, the current projection, and the session-local undo
/// and redo stacks. The stacks are never persisted (R8.4.2).
#[derive(Debug)]
pub struct Session {
    actor: Uuid,
    /// The state the log replays on top of: FORMAT-SPEC §5's snapshot role.
    /// Empty for a session that starts from nothing.
    baseline: Document,
    log: OperationLog,
    projection: Projection,
    undo: VecDeque<StackEntry>,
    redo: VecDeque<StackEntry>,
    undo_capacity: usize,
    redo_capacity: usize,
    dirty: bool,
    /// Non-blocking diagnostics: capacity drops (R8.4.4), stale discards.
    diagnostics: Vec<String>,
}

impl Session {
    /// Opens an empty session for a fresh actor.
    pub fn new() -> Self {
        Self::with_actor(Uuid::now_v7())
    }

    /// Opens an empty session for a named actor.
    pub fn with_actor(actor: Uuid) -> Self {
        Self {
            actor,
            baseline: Document::default(),
            log: OperationLog::new(),
            projection: Projection::default(),
            undo: VecDeque::new(),
            redo: VecDeque::new(),
            undo_capacity: DEFAULT_UNDO_CAPACITY,
            redo_capacity: DEFAULT_REDO_CAPACITY,
            dirty: false,
            diagnostics: Vec::new(),
        }
    }

    /// Sets both stack capacities. R8.4.4: the two bounds are independent, and
    /// exhausting one leaves the other unchanged.
    pub fn with_capacities(mut self, undo: usize, redo: usize) -> Self {
        self.undo_capacity = undo;
        self.redo_capacity = redo;
        self
    }

    /// This session's actor id.
    pub fn actor(&self) -> Uuid {
        self.actor
    }

    /// The current projection's document.
    pub fn document(&self) -> &Document {
        &self.projection.document
    }

    /// The current projection, including tombstones and discards.
    pub fn projection(&self) -> &Projection {
        &self.projection
    }

    /// The durable operation log.
    pub fn log(&self) -> &OperationLog {
        &self.log
    }

    /// Whether the document has changed relative to the saved target.
    pub fn is_dirty(&self) -> bool {
        self.dirty
    }

    /// Clears dirty. §9.1's save contract is the only thing that may call this.
    pub fn mark_saved(&mut self) {
        self.dirty = false;
    }

    /// Non-blocking diagnostics accumulated this session.
    pub fn diagnostics(&self) -> &[String] {
        &self.diagnostics
    }

    /// Number of entries available to undo.
    pub fn undo_depth(&self) -> usize {
        self.undo.len()
    }

    /// Number of entries available to redo.
    pub fn redo_depth(&self) -> usize {
        self.redo.len()
    }

    /// Commits a local command as one atomic batch and one undo entry.
    ///
    /// R8.2.1: exactly one undo entry per accepted operation batch. R8.4.1:
    /// an accepted local command outside redo execution clears the redo stack.
    ///
    /// The document is validated BEFORE the batch enters the log. A command
    /// that would produce an invalid document is rejected atomically with zero
    /// effects and no undo entry (R8.2.2, FORMAT-SPEC §4.3 row 1) — the log
    /// must never contain a batch whose projection is invalid, because replay
    /// has no way to decline it later.
    pub fn commit(&mut self, operations: Vec<Operation>) -> Result<Uuid, CommandError> {
        let inverse = invert_against(&self.projection.document, &operations)?;
        let id = self.apply_local(operations.clone())?;
        self.push_undo(StackEntry {
            forward: operations,
            inverse,
        });
        self.redo.clear();
        Ok(id)
    }

    /// Undoes the most recent command, appending a compensating batch.
    ///
    /// Returns the compensating batch's id, or `None` when the undo stack is
    /// empty. R8.4.1: compensation batches generated by executed undos do NOT
    /// clear redo.
    pub fn undo(&mut self) -> Result<Option<Uuid>, CommandError> {
        let Some(entry) = self.undo.pop_back() else {
            return Ok(None);
        };
        let ops = StackEntry::refreshed(&entry.inverse);
        match self.apply_local(ops) {
            Ok(id) => {
                self.push_redo(entry);
                Ok(Some(id))
            }
            Err(e) => {
                // Restore the entry: a failed undo must leave the stacks as
                // they were, exactly like a rejected command (R8.2.2).
                self.undo.push_back(entry);
                Err(e)
            }
        }
    }

    /// Redoes the most recently undone command.
    ///
    /// R8.1.3: this restores the SAME entity ids the undone command created,
    /// including reopening a tombstone written by this session's own undo.
    /// That authorization is exactly what [`crate::replay`] checks by
    /// provenance, and this is the only place that mints such a create.
    pub fn redo(&mut self) -> Result<Option<Uuid>, CommandError> {
        let Some(entry) = self.redo.pop_back() else {
            return Ok(None);
        };
        let ops = StackEntry::refreshed(&entry.forward);
        match self.apply_local(ops) {
            Ok(id) => {
                self.push_undo(entry);
                Ok(Some(id))
            }
            Err(e) => {
                self.redo.push_back(entry);
                Err(e)
            }
        }
    }

    /// Accepts an external or replayed batch: sync-delivered, recovery-restored
    /// or CLI-applied.
    ///
    /// R8.3.1: an accepted external batch clears BOTH stacks, so local undo
    /// never crosses one. R8.3.2: it never enters them. R8.3.3: it makes the
    /// document dirty relative to the saved target.
    pub fn accept_external(&mut self, batch: Batch) -> Result<Delivery, CommandError> {
        let delivery = self.log.deliver(batch)?;
        self.reproject();
        if delivery == Delivery::Accepted {
            self.undo.clear();
            self.redo.clear();
            self.dirty = true;
        }
        Ok(delivery)
    }

    ///
    /// This is [`Self::open_with`] for a package that has been compacted: the

    pub fn open_snapshot(

        s.baseline = baseline;
        s.open_with(batches)?;
        Ok(s)

    /// The snapshot this session replays on top of.
    pub fn baseline(&self) -> &Document {
        &self.baseline
    }

    /// Replays batches while CONSTRUCTING this session's projection.

    /// R8.4.2: batches replayed while constructing an open are part of that

    pub fn open_with(&mut self, batches: Vec<Batch>) -> Result<(), CommandError> {

            self.log.deliver(batch)?;

        self.reproject();
        self.undo.clear();
        self.redo.clear();
        self.dirty = false;
        Ok(())

### 1. Held batches bypass duplicate-ID and overlapping-range validation

`check_framing` compares only against `accepted`; held IDs and ranges are not indexed. `promote_held` removes a batch and calls `accept` without re-running framing ([log.rs:183](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/log.rs:183), [log.rs:241](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/log.rs:241)).

Concrete duplicate-ID case:

```text
H1 = B(Q, A, 1, {X:1}, [create Level E1])
H2 = B(Q, A, 2, {X:1, A:1}, [create Level E2])
G  = B(G, X, 1, {},    [create Level EG])

deliver(H1) -> Held
deliver(H2) -> Held
deliver(G)  -> Accepted
```

Correct: `H2` is rejected for reusing batch ID `Q`.

Actual: `H1` and `H2` are both promoted and accepted. `ids.insert(Q)` in `accept` does not report that `Q` was already present. The accepted log therefore contains two different batches with the same batch ID.

Concrete overlap case:

```text
H1 = B(Q1, A, 1, {X:1},      [create E1, create E2])  // range 1..=2
H2 = B(Q2, A, 2, {X:1, A:1}, [create E3, create E4])  // range 2..=3
G  = B(G,  X, 1, {},          [create EG])
```

Both held batches are accepted after `G`; counter 2 is reserved twice. Correct: `H2` must be rejected as `OverlappingRange` before replay.

There is also direct arrival-order dependence:

```text
R = B(R, A, 1, {X:1}, [create Level ER])
S = B(S, A, 1, {X:1}, [create Level ES])
```

Delivering `R,S,G` retains `R` and silently drops `S`; delivering `S,R,G` retains `S` and drops `R`. `promote_held` mistakes the loser for an I2 duplicate solely because its range is now below the watermark ([log.rs:189](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/log.rs:189)). Thus claims 1 and 2 are false for the same delivered set.

- The three-branch I5 classifier itself is sound for a correctly ordered history: it uses each operation’s `write_position(index)`, distinguishes `created_at >= at`, live interval, and `deleted_at < at`, and evaluates later operations against earlier operations in the same scratch batch. Both held batches are accepted after `G`; counter 2 is reserved twice. Correct: `H2` must be rejected as `OverlappingRange` before replay.

There is also direct arrival-order dependence:

```text
S = B(S, A, 1, {X:1}, [create Level ES])
```

Delivering `R,S,G` retains `R` and silently drops `S`; delivering `S,R,G` retains `S` and drops `R`. `promote_held` mistakes the loser for an I2 duplicate solely because its range is now below the watermark ([log.rs:189](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/log.rs:189)). Thus claims 1 and 2 are false for the same delivered set.

### 2. A range straddling the baseline watermark is accepted and replayed

Concrete case:

Correct: reject the whole batch. Counters 4 and 5 are already covered by the snapshot; a batch cannot be split around the watermark.

Actual:

### 3. Frontier regression reverses one actor’s own causal order

Concrete batches:

```text
Y1 = B(Y1, Y, 1, {},      [create EY1, create EY2])   // range 1..=2
A1 = B(A1, A, 1, {Y:2},   [create Level E name="old"])
A2 = B(A2, A, 2, {A:1},   [setFields E {"name":"new"}])
```

Deliver `Y1`, `A1`, `A2`. All are accepted.

The positions have causal-past sizes 0, 2, and 1 respectively, so sorting by `(causalPastSize, counterBase, actorId)` places `A2` before `A1`. Replay consequently classifies the set as `BeforeCreation`, discards `A2`, and leaves `E.name == "old"`.

Correct: actor counter 2 is causally after actor counter 1, so `A1` must precede `A2` and the result must be `"new"`. Alternatively, `A2` must be rejected for omitting the inherited `{Y:2}` causal past.

`prerequisites_present` establishes only that named frontier counters and the actor’s previous counters exist; it does not establish causal closure or frontier monotonicity ([log.rs:210](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/log.rs:210)). Therefore the assertion underlying `canonical_order` is not enforced ([log.rs:329](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/log.rs:329)).

### 5. Invalid and identity-changing `setFields` operations are accepted

After creating `Level E`:

```text

```

Correct: reject the command before it enters the log because `name` has the wrong type.

Actual: `merge_fields` cannot deserialize the result and returns `None`; `apply_operation` silently does nothing ([replay.rs:270](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/replay.rs:270)). `would_be` sees the unchanged valid document, so `Session::commit` accepts the batch, marks dirty, and pushes an undo entry.

Similarly:

```text
setFields E {"type": "not-a-real-entity-type"}
```

is silently accepted as a no-op rather than rejected.

Identity is worse:

```text
setFields E {"id": E2}
```

If the resulting entity deserializes, `merge_fields` returns an entity whose ID is `E2`. `apply_operation` inserts that entity but never removes target `E`; it cannot, because `insert_entity` receives only the updated entity. The document therefore retains `E` and gains/replaces `E2`, while the live interval remains keyed only by `E`. Undo captures `"id": E`, targets `E`, and cannot remove the inserted `E2`.

Correct: `id` and `type` must not be writable as ordinary fields, or the operation must be validated with explicit identity/type invariants before replay.

### 6. `invert_against` mishandles LWW4 create collisions

Actual inverse after reversal: `[delete(E), delete(E)]`. During undo, the second delete is stale, so B1 discards the whole compensating batch. `undo()` returns an error, restores the stack entry, but the discarded compensation batch remains accepted in the durable log.

### 8. Promotion of a previously held external batch does not fire the session fence

Concrete sequence:

```text

External:
```

Actual: `OperationLog::deliver(C2)` reports only `Accepted` for the supplied local batch; it does not report promoted batches. The session finishes with undo entries for both `C1` and `C2`, crossing the accepted external batch ([session.rs:179](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/session.rs:179), [session.rs:243](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/session.rs:243)).

## Verification and sound areas

- `promote_held` cannot loop forever: every successful iteration removes one element from the finite held vector. It does, however, improperly drop conflicts and accept malformed promoted batches as described above.
- B1 document/interval rollback is complete. Both are cloned and assigned back only after every operation succeeds. The only direct mutation on failure is `p.discarded`, which is the intended discard record, not a partial document effect ([replay.rs:168](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/replay.rs:168)).
- The three-branch I5 classifier itself is sound for a correctly ordered history: it uses each operation’s `write_position(index)`, distinguishes `created_at >= at`, live interval, and `deleted_at < at`, and evaluates later operations against earlier operations in the same scratch batch. Finding 3 breaks the ordering supplied to it; finding 4 breaks restoration authorization.
- For schema-valid, identity-preserving `setFields`, sequential canonical replay implements per-field LWW correctly: each update starts from the current entity and changes only named top-level fields. Later deletes tombstone the target, and subsequent sets are stale.
- Fresh undo/redo operation IDs and batch IDs are implemented, and entity IDs are preserved. The two capacity queues are independently bounded and each drops only its own oldest entry.
- Ordinary `open_with` replay does not fire the external fence and leaves the session clean as claimed. Direct `accept_external(…)=Accepted` clears both stacks. The missing case is an external batch promoted during a later local delivery.
- Hash iteration does not affect normal canonical document output: frontiers are converted to `BTreeMap`, and projection lookups do not iterate intervals. However, after exploiting finding 1 to create overlapping accepted ranges for two actors, `validate_retained` returns whichever actor its `HashMap` visits first, so the reported `CounterGap` is nondeterministic ([log.rs:290](/Users/dawidlaszuk/projects/personal/domowik/crates/domowik-document/src/log.rs:290)).
