# Domowik project state — 2026-09-06

Status: **review snapshot.** An independent read of the repository, its
tracker, and its verification, plus live reproduction of the claims that
mattered. Written against commit `0fa2b57` with the issue-0055 working tree
uncommitted. This is an assessment, not a decision record; where it disagrees
with a specification, the specification wins.

## Verdict

The engine is real and good. The product is not a product yet.

Roughly **60–70% of the engineering for a 2D MVP is done**, but the remaining
30–40% is concentrated in the two things a floor-plan editor is actually
judged on — snapping and room identity — plus the whole of the platform and
release work, none of which has started.

## What works, verified rather than read

The README flow was run end to end against a binary built from the working
tree:

```text
5 walls + 1 door -> splits and joins applied atomically
Level 1 - 2 room(s):  13.15 m^2  /  9.27 m^2   (inner-face areas)
validate: valid.   export-svg: Wrote f.svg (7 wall(s)).
```

That is the hard part of this domain and it is done. Twenty CLI commands.
Real join and split semantics in atomic batches. Planar face extraction with
holes. Inner-face area measurement. Undo by compensating batch. A
content-addressed asset store. Container persistence with an
injected-save-failure suite that reproduces filesystem states rather than
claiming a power-loss guarantee it cannot test. SVG and PNG export.

The performance work is first-class rather than aspirational.
`docs/BENCHMARK-INTERACTION.md` carries a named-host corpus up to `campus-xl`
(4 levels, 1,345 walls) with p50/p95/p99 and allocation counts. The quadratic
session-commit defect inherited from the Go spike was diagnosed and fixed
*before* Phase 2 rather than discovered inside it: 48.6 ms to 197 us, a 247x
improvement. The exact-predicate discipline AGENTS.md demands is being
followed — filtered orientation at 1.75 ns, exact fallback at 42.8 ns, with an
integer oracle checking all 360,000 pairs of directed segments on a 5x5 grid.

Code hygiene is unusually strong: **zero** `TODO`, `FIXME`, `todo!` or
`unimplemented!` in `crates/`, and only **18** `unwrap`/`expect` outside test
modules across 30k lines.

## Two red states at the time of writing

### 1. The working tree fails `cargo clippy`

The uncommitted issue-0055 work trips `needless_range_loop` at
`crates/domowik-geometry/src/dyadic.rs:285`. One line. The WIP itself is
correct — the issue's own reproduction now refuses as R3.1.2 requires:

```text
domowik: collinear-overlap: walls ... overlap along their axes   (exit 1)
```

and the document, log and file bytes are untouched.

### 2. `verify.sh` fails on a clean checkout of committed `HEAD`

Run in a detached worktree at `0fa2b57`, verification failed at
`spike 0024 Flutter macOS application`:

```text
error: Build input file cannot be found:
  '.../domowik_bridge_plugin/macos/rust/libdomowik_bridge.a'
```

Isolated across four builds:

| State | Result |
|---|---|
| `flutter clean` + archive absent | **BUILD FAILED** |
| `flutter clean` + archive present (even stale) | Built |
| no clean + archive absent | Built |
| no clean + archive present | Built |

Xcode's build-input existence check for the `-force_load` archive runs
*before* the pod script phase that produces it.
`flutter_plugin/macos/.gitignore` ignores `rust/`, so a fresh clone has no
archive: the first `verify.sh` run fails and every later run passes. It
passes on the maintainer's machine because a 62 MB untracked archive is
present from an earlier build.

This is **not** issue 0056. That one is an intermittent duplicate Swift SDK
module map (`_SwiftConcurrencyShims` and friends); this is deterministic and
has a different error. Filed as issue 0057.

The reason it went unnoticed is issue 0061: CI runs `ubuntu-24.04` only, and
the macOS stages test `uname -s`, so **the entire GUI half of `verify.sh`
executes nowhere but the maintainer's laptop.**

## What is left for an MVP

The repository defines no MVP. The closest existing definition is the Phase 2
exit criterion — "a real apartment can be edited on reference desktop/mobile
devices; GUI edits replay through the CLI; 2D output is semantically
equivalent within documented rendering tolerances" — plus a shippable v0.1.
Measured against that:

### Tier 1 — the editor is not usable without these

**Snapping and magnetism (BEHAVIOR-SPEC section 6, normative, 539 spec
lines).** Effectively unimplemented. Only R6.3's winner comparator exists, and
only because hit-testing reuses its ordering and deduplication rules — with a
disclosed conformance caveat that R6.3.1 says *exact* while the bridge
computes in binary64. Section 6.1 candidate inventory, 6.2 angle targets, 6.4
guides and temporary disable, 6.5 pointer and capture lifecycle, and the
entire S-series fixture set: nothing. The Flutter app carries a six-line
ad-hoc axis snap. **This is the single largest remaining item and it is the
difference between a demo and a tool** — nobody draws a floor plan freehand
without magnets. Issue 0058.

**Room identity and metadata (section 5.2, normative).** No reference to
`R5.2` anywhere in `crates/`. There is no room record entity, so a room cannot
be named. It also means the size corpus measures 960 of its 1,000 entities and
`unfurnished-1000-v1` stands as a lower bound. Issue 0060.

**Marquee selection (section 7.3).** The core region query exists in
`domowik-geometry::hit`; the gesture and selection semantics do not. Issue
0049 deferred it explicitly and modifier-drag over empty canvas is wired to do
nothing on purpose. Issue 0059.

**Wall contact admission (issue 0055).** In flight, roughly half. Axis
refusals land; `wall-area-overlap` warnings and intersection-construction
conformance are outstanding.

**Opening field set (issue 0010).** `depthMm`, `side`, `hinge`,
`opensToward`, `swingDeg` are all missing. Doors have no swing direction, and
that is visible in every 2D export.

**Wall detach (R3.3.7).** No CLI command and no GUI gesture; only a synthetic
batch in the benchmark harness.

### Tier 2 — platform and delivery, essentially not started

- **macOS only.** Linux and Android bridge validation (issue 0024) is owed;
  Android additionally needs toolchain the machine does not have. ADR 0003
  stays Proposed until it passes.
- **Issue 0033 is fully open** — eleven acceptance criteria, none met. No
  reference devices, no frame budgets, no input-latency bound. Every
  performance number so far is CPU-side and explicitly disclaims being a
  frame budget.
- **No release exists.** Nothing tagged, ADR 0007 still Proposed, no Rust
  SBOM process, cross-build compile-only on two Linux targets. The CI comment
  claiming `domowik-cli` has no binary target is stale — there is a
  `[[bin]] name = "domowik"`.
- **Issue 0034 (identity) is blocked and blocks 0018.** No namespace
  reserved, no application IDs chosen, registry checks incomplete. Nothing
  publishes until it lands, and it is largely not engineering work.
- **Migrations (issue 0031).** The framework does not exist; the first
  release creates the obligation.

### Tier 3 — known engine debt, not MVP-blocking

- **R5.1.9 scoped invalidation is measured and unmet.** Every accepted batch
  rebuilds the whole level: `campus-xl` recomputes all 329 walls where the
  closure permits 54. The locality oracle is implemented and a canary test
  fails when the scope is fixed. Fine at 2.66 ms today; a ceiling later.
- **No renderer-neutral paint API.** `svg.rs` and `png.rs` render straight
  from the document, so they can drift and there is nothing to write
  serialization-independent conformance tests against.
- **`lwwHorizon` is unfixated** — an owner decision blocking format
  ratification, mostly a Phase 4 concern.
- Validation exit-code taxonomy (three codes exist, six are specified),
  `ops --json`, golden and adversarial corpora, real fault injection.

### Promised by the README, not in any plan

Furniture and asset instances (section 10) is a "To define" stub. The README
says "placing openings and furnishings". If furnishing is MVP, add a
specification effort on top of everything above.

## Suggested order

1. Fix the clippy error; land issue 0055; take issue 0057 so verification is
   reproducible from a clean checkout again.
2. **Issue 0058, snapping.** Largest, highest leverage, gates any honest
   usability claim.
3. **Issue 0060, room records.** Small specification, unblocks naming *and*
   closes the size-corpus caveat.
4. Issue 0059 marquee, plus detach and the opening field set — three small
   ones that close visible holes.
5. Issue 0061 so CI covers what only the laptop covers today.
6. Issue 0033, then Linux validation. Only then discuss release, which means
   unblocking issue 0034 first.

## Changed after this snapshot was written — 2026-09-06

Recorded here rather than folded in, so the review above stays readable as
what was found.

**Six issues were filed from these findings:** 0057 (the clean-checkout macOS
build defect), 0058 (snapping), 0059 (marquee), 0060 (room records), 0061 (CI
runs no macOS or GUI stage), and 0062 (retire the Go toolchain).

**The Go toolchain was cut back the same day** under issue 0062.
`internal/evidence/phase0` and the superseded `spikes/0024-flutter-go-bridge/`
were deleted; `domowik-jsoncheck` and `domowik-tracker-check` were ported to
`crates/domowik-devtools` with no new dependency, after their behaviour was
proven identical to the Go originals on every success and failure path.
`internal/corpusgen` is now the only Go package in the active tree, and whether
to port or freeze it is an open question for the owner. Two of the Go stages
being retired were guarding an empty set: `dependency drift` runs `go mod tidy`
against a module with no `go.sum` and no requires.

**The Tier 3 list above is unchanged**, and so is every Tier 1 and Tier 2 item.
Retiring a build tool does not move the MVP.

## The thing worth saying plainly

The engineering discipline here is exceptional. The Phase 1 closure record
lists what Phase 1 did *not* deliver. The adversarial audit downgraded four
issues and found three real defects hiding behind the paperwork. Twenty-three
issues carry the honest label "partial scope" rather than a green check. That
is rare, and it is the reason this review could be written quickly and with
confidence.

The risk is the mirror image of that strength: **268 `docs` commits against 72
`feat` commits**, and 11k lines of specification plus a 6k-line decision log
against 30k lines of implementation. The specification is running well ahead
of the code, and the two normative sections that matter most for a usable
editor — section 6 snapping and section 5.2 room identity — are both fully
specified and entirely unbuilt.

The gap to MVP is not analysis. It is building those.
