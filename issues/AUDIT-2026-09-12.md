## Findings

and prose verdicts have been maintained independently since ED-0095, which
wrote its closure decisions as paragraphs and left every box alone. Twelve
criteria across 0015 and 0037 were unticked while both read `Done`. Read the
notes, not the boxes.

**F2 — Two issues have fully-ticked checklists their own later notes
contradict.** Close neither on its boxes.

- **0010** shows 5 of 5 ticked, and its gap has NARROWED since the snapshot.
  Main's room work landed `RoomRecord`, so `Entity` now has five variants
  (`Level`, `Wall`, `Opening`, `WallJoin`, `RoomRecord`), and `Opening` now
  carries `depthMm`, `side`, `hinge`, `opensToward` and `swingDeg`. **Both of
  those were listed as missing in the snapshot and are disproven.** What is
  still real: none of FORMAT-SPEC §2.3's **Tier B** kinds `label`, `dimension`
  or `assetInstance` exists, `Wall` carries no style reference field, and
  property coverage is example-based. Criterion 1 is still unmet, for less than
  the snapshot claimed.
- **0036** shows 6 of 6 ticked, every one for the Go product. ED-0096 restored
  the issue from `done/` for exactly this reason.

**F3 — Notes go stale, and this tracker has no mechanism that notices.** Two of
the residuals in revision 1 were a month out of date because the issue's own
note was. 0012's criterion text still says distances "use binary64 arithmetic"
after `4dd59ff` made point comparison exact; 0014's ED-0096 note still says
there is no warning class after 0054/0055 added one. **The criterion text inside
0012 is itself now wrong and needs its owner to correct it.** Before closing any
issue, re-read the code, not the note.

**F4 — 0015 was `Done` with an unmet criterion, and has been reopened. The
criterion is unmet for a different reason than revision 2 gave.**

Revision 2 said no specification row names a nesting-depth bound. **That is
false.** FORMAT-SPEC §9.3 row **L11** is Ratified: "JSON/object serialization
nesting depth | 128 | ... reject when depth would exceed 128 (**depth == 128
parses**)", and §2 line 320 names it among the parser ceilings. The row exists
and always did.

The real defect is narrower and worse:

1. **No explicit guard.** `Limits` has no depth field, so a ratified ceiling is
   inherited from whatever `serde_json` happens to default to rather than
   enforced by the reader.
2. **An off-by-one, in the rejecting direction.** L11 requires depth 128 to
   PARSE. `format0004` measured `serde_json`'s default as REJECTING depth 128.
   The implementation therefore refuses a document the format requires it to
   accept. L11's own notes cite "serde_json default recursion limit 128" as the
   precedent for the value, which is how an inclusive spec bound and an
   exclusive library limit came to be treated as the same number.

This strengthens the reopening rather than weakening it: a missing guard is a
gap, and rejecting conformant input is a conformance defect. **0015 stays
`In Progress (partial scope)`.** Contract and fix belong to issue 0004
(`format0004`); the hostile fixture to 0028.

**F5 — Three issues carry criteria naming a superseded world.** Each needs its
owner to restate the criterion against the Rust product. Deleting them to reach
a terminal status is forbidden by ED-0102.

- **0024** criterion 2 requires a "Dedicated **Go** bridge package"; criterion 6
  adds evidence to **ADR 0002**. The bridge is Rust (ED-0091) and ADR 0002 is
  superseded by ADR 0008. Criterion 1, Linux and Android, is **not** obsolete.
- **0036** criterion 2 checks component sets against "resolved **Go** modules …
  the **Go** toolchain/stdlib/runtime".
- **0006** and **0007** are titled "Spike … **in Go**". The substance was
  delivered in Rust and their evidence criteria are met.

**F6 — Missing tooling is not obsolete scope.** Linux and Android requirements
stay open while their toolchains are provisioned. ED-0102 applies in terms:
unfinished is not obsolete.

**F7 — 0030 is the largest single unblocker.** It gates 0006, 0007, 0012, 0013
and 0055 through the ED-0011 gates and the five open questions in
NUMERICAL-MODEL §12. Nothing else unblocks five issues.

**F8 — six advisory rounds produced no adversary, and this document has not
had an independent review.** Six `codex exec` runs against `gpt-5.6-sol` at
high reasoning effort, the startup banner verified on every one, returned no
findings. Every run terminated before writing its verdict, under four different
prompt shapes: a full brief, a verdict-forcing template, claims stated inline
to keep tool output small, and the same again with the scope widened to the
checker. One round additionally auto-loaded an unrelated `adversarial` skill
because the word appeared in the prompt.

A `context7` MCP authentication error is logged at `SessionStart` on every run.
It is **not** the cause: the last run emitted it and still began a turn. The
consistent symptom is that `codex exec` ends the run before the final message,
independent of prompt shape. That is an environment defect in the advisory
seat, not something a prompt can repair, and it needs fixing before this
project can rely on the review INSTRUCTIONS.md requires.

No round's side is written here. What replaced it is a self-check that
mechanically re-derived every checkable claim; it found one further defect, the
count of unassigned Phase 1 issues, corrected from seven to nine. **An
independent review is still owed on this document.**

repository **exists and has been pushed** — `git@github.com:laszukdawid/domowik.git`,

   `go.mod` entirely, which resolves it by deletion — worth sequencing

   the resulting lookups as MANUAL-ONLY and unperformed. NAMING.md's own release
   gate requires each to be re-executed through its interactive interface.
   crates.io is the one that matters, since the product is now Rust.
